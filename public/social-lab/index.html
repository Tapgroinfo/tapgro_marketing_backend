Why we don’t use @zernio/node yet

              
Our Nest ZernioClient is a thin REST wrapper so the API key, logs, and errors stay inside TapGro.

            

          

          

            

              
Current approach

              
    
                
  • API key from settings.socialProvider.apiKey (DB), not only env
    • 
                
  • Every write logged to Integration Logs
    • 
                
  • Errors mapped to Nest HTTP exceptions
    • 
                
  • Same service used by Admin + Customer portals
    • 
              

            

            

              
When to adopt the SDK

              
    
                
  • Posts / comments / inbox / analytics (typed methods)
    • 
                
  • Less hand-written path strings
    • 
                
  • Built-in RateLimitError / ValidationError
    • 
              

            

            

              
How to use the model (SDK) later

              
npm install @zernio/node

import Zernio from '@zernio/node';

// Prefer injecting apiKey from SettingsService — do not rely only on env in Nest
const zernio = new Zernio({
  apiKey: settings.apiKey,          // from DB
  baseURL: 'https://zernio.com/api',
  timeout: 60000,
});

// 1) Profile (one per salon / customer)
const { data: created } = await zernio.profiles.createProfile({
  body: { name: 'Glow Salon', externalId: 'customer:64f…' },
});
const profileId = created.profile._id;

// 2) Connect Instagram / Google / Facebook
const { data: connect } = await zernio.connect.getConnectUrl({
  path: { platform: 'instagram' }, // googlebusiness | facebook
  query: { profileId, redirect_url: 'https://api…/callback' },
});
// open connect.authUrl in browser

// 3) List accounts → post / comments / DMs
const { data: listed } = await zernio.accounts.listAccounts({ query: { profileId } });
await zernio.posts.createPost({
  body: {
    content: 'Hello',
    mediaItems: [{ type: 'image', url: 'https://…' }],
    platforms: [{ platform: 'instagram', accountId: listed.accounts[0]._id }],
    publishNow: true,
  },
});

              
Docs: docs.zernio.com/sdks/node · Keep Nest wrapper; call SDK inside ZernioClient when we expand posts/inbox.
